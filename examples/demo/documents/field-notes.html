FIELD NOTES / ISSUE 003 / NIMBLE TERMINAL

Small tools.
Long journeys.

A field guide to documents that feel at home in a terminal, a browser, or a machine far from the network.

A fictional editorial specimen · 4 minute read

01 / Start with the page

A useful document is a sequence of ideas. A heading sets the direction. A paragraph develops the thought. A table makes a comparison easier to read. These familiar forms work without a full browser engine.

For a portable renderer, the important question is not how many features can fit. It is how clearly a small set of features can express the work in front of us.

“Carry the document, not the machinery around it.”

02 / Respect the surface

On a modern terminal, pixels can carry fine type and quiet borders. On a simpler display, half-block glyphs provide a useful preview. In the browser, the same Go layout becomes a canvas image.

The document stays recognizable. The host decides how to show it, how to scroll it, and how to combine it with the rest of the application.

03 / Keep the edges visible

Explicit limits are part of the design. A document should have a known cost: a bounded input, a bounded tree, and a bounded output image. Unsupported features should degrade predictably.

This specimen uses only headings, paragraphs, inline emphasis, line breaks, spacing, backgrounds, and color. Its long page is also a useful test of scrolling and zoom.
